## 3. Decisions taken on your behalf

1. **Band breaches:** a breach of the default tomato profile on a greenhouse with no saved overrides stays in `scada_anomalies` but does not raise an anomaly. Not pinned by a test; no ADR written.
2. **Robust upload gate:** off by default. The upload LSTM threshold therefore still flags about 0.1% of rows in any file.
3. **Old CUSUM:** non-voting. At K = 0.25, H = 4 it alarms every 35–41 samples on stationary noise; the catalog's "about 340" was wrong.
4. **History-based Mahalanobis:** non-voting (see above).
5. **Ensemble:** left without a tenant baseline, i.e. inert. Given a real baseline it flagged 19 of 167 clean windows and added no detections.
6. **Noise ratio 30:** zero clean flags, at the cost that 0.5 °C noise is caught in 16 of 40 single real windows (1 °C noise: 40 of 40).
7. **Drift watch accepted** with the paired-probe input slightly over budget and the RH input in shadow; left unwired.
8. **No minimum window count for noise calibration:** measured, and a minimum would be worse than calibrating from one window (the fixed baseline flags 76% of clean windows).

## 4. What is left, in priority order

1. **Full QA wave and hardened harness.** Seeded-database mode, recall on real windows, amplitude sweep, a second fixture, migration 029 on Postgres, a test pinning the band-breach behaviour. Keep the 0.90 bar.
2. **Cold-start humidity noise baseline.** Before calibration about half of clean windows are flagged on humidity; the fixed humidity baseline is about five times too low. The live scorer also refuses those windows for its calibration ring.
3. **Small spikes and single-sensor bias.** A +1.5 °C single-sample spike is not detected. The EMA bias check needs 288 samples and the window is 20, so it never runs.
4. **Mahalanobis recalibration, then re-arm.** Condition the reference on time of day; take the cutoff from the history's own distance distribution.
5. **Ensemble: rework or remove.**
6. **Drift watch:** persistence per tenant, greenhouse and input; upload wiring in shadow mode; a better residual model for RH.
7. **Upload:** LSTM percentile threshold; humidity and CO₂ spikes (MAD cannot do it for humidity: no floor gives zero clean hits and still catches spikes).
8. **Structural:** one scoring path for upload, live and `/api/inference`; denormalise before every physical rule (BACKLOG-23); use the VAE latent; persist the live clean-window ring across restarts.
9. **Blocked on data:** live climate rules (live readings carry no setpoint or outdoor values).
10. **Process:** code review, ADR for the band-breach change, `CLAUDE.md` baseline line, `AGENT_MEMORY.md` entries, PR.

**Evidence**

- The gate runs on an empty database. A seeded run showed more clean flags; the seeded script exists only outside the repo (in the scripts archive sent with this note).
- Two agent reports disagree on whether a +3 °C single-sample spike is detected (100% versus 0%). Not resolved.
- "Current" noise-recall figures differed between reports from the same agent; I used the last sweep.
- The over-heating rule's false-alarm rate after the fix was never measured (the harness supplies no outdoor or solar context).
- Joint-implausibility detection was measured only in the seeded run, not by the gate.
- The 17 mismatch fixes were verified by an agent reading the code, not by tests.
- Measurement scripts and the copy of the tenant file lived in the cloud workspace and are gone when the session ends, apart from what was sent with this note.

**Parked experiments (local to the cloud session, not on GitHub)**

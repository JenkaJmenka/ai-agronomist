🏛️ What the Architect Actually Does

The Architect is technically deep but doesn't code features. Instead, they:

✓ Review code for architectural soundness (not just bugs)
✓ Question assumptions: "Why LSTM-VAE over Isolation Forest?"
✓ Assess scalability: "Will this work for 10+ customers?"
✓ Catch technical debt early
✓ Document decisions in ADRs (Architecture Decision Records)
✓ Run weekly architecture sync
✓ Identify anti-patterns before they become problems

📋 Weekly Architect Checklist

Every Friday (30 min sync):

☐ Any new dependencies added? Justified?
☐ Database schema changes? Migration tested?
☐ API contract changes? Breaking changes?
☐ New error modes identified? SLA impact?
☐ Model accuracy trend? Regression detected?
☐ Performance baseline hit? Optimization needed?
☐ Phase 1.5 risk assessment (ongoing)

🚨 Red Flags Architect Catches

🛑 STOP WORK (P1)

• Tight coupling (LSTM-VAE + Isolation Forest)
• Schema doesn't scale to 5+ customers
• No monitoring configured
• Model checkpoint without metadata
• Secrets in code
🟡 DISCUSS (P2)

• Premature optimization
• Monolithic API endpoints
• Silent failures
• Hard-coded thresholds
• Code duplication

⚡ Example: LSTM-VAE vs Isolation Forest Decision

1
ML Engineer proposes: "LSTM-VAE because it learns latent representations of normal patterns"
2
Architect questions: "Why not Isolation Forest only? What's the inference latency impact?"
3
Team discusses: "LSTM has better pattern learning but slower. What about ensemble?"
4
Decision documented: ADR-001 filed: "LSTM-VAE + Isolation Forest ensemble"
